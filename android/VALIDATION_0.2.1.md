# EyeCare 0.2.1 변경과 검증

작성일: 2026-10-10. 10월 9일 실기기 기록의 62.8% 커버리지와 부분 관측 표시 문제를 바탕으로 개발했다.

## 변경 사항

- 엔진 `exposure-0.2.1`: 긴 표본 간격, 기준 표본 대기, 종료 직전 미관측, 진행 중 대기, 상태 전환 경계를 분리한다. 유효 간격 한도 1,500ms와 큰 변화 판정 기준은 유지한다.
- 10초별 제외 사유와 시간을 저장한다. 구간별 유효 시간과 제외 시간의 합계를 검사할 수 있다. 숨김·크기 변경·어두움·읽기 실패의 분류는 관찰 상태이며 원인의 확정 진단이 아니다.
- 캡처 콜백, 획득 성공·실패·빈 획득, 빈도 제한 생략, 숨김 생략, 선택 표본, 픽셀 읽기 실패, 크기·가시성 전환 횟수를 집계한다.
- 엔진 입력, 어두운 표본, 무효 표본, 유효 쌍, 긴 간격, 연속성 초기화 횟수와 표본 간격 분포를 기록한다. 분포 범위는 550ms 이하, 550–1,000ms, 1,000–1,500ms, 1,500ms 초과다.
- 결과 그래프의 부분 분석 구간은 회색으로 표시한다. 구간별 유효/전체 시간과 새 기록의 제외 사유를 펼쳐 볼 수 있다. 그래프 시간축은 종료까지 포함한다.
- 새 세션을 종료하면 해당 결과의 응답란을 연다. 화면 잠금·프로세스 재진입 뒤에도 미완료 응답이 있는 기록을 제안한다. 과거 0.1·0.2 기록은 기존 방식으로 유지한다.
- 사용 종료 후와 휴식 시작 이후 응답을 각각 시각과 함께 저장한다. `건너뛰기`는 점수 0과 구별한다. 휴식 요청 후 응답 또는 건너뛰기를 선택하면 타이머로 이어지고, 돌아오면 같은 기록의 휴식 이후 응답을 받는다.
- 새 보고서는 스키마 2이며 수집기는 스키마 1과 2를 모두 지원한다. 구간 합계·진단 정보·응답 상태를 검증하고 높은 revision으로 수정 내용을 반영한다.
- 대시보드는 처음 열 때 최신 엔진을 선택한다. 혼합 엔진·부분 관측을 표시하고 구간별 품질 표, 캡처 횟수와 표본 간격 분포를 제공한다. 응답 시각은 CSV에도 포함한다.

## 응답 해석

기존 `discomfort`는 시점 미상의 기존 응답으로 보존한다. 새 `feedback.afterUse`와 `feedback.afterRest`는 별도 필드이며 서로 덮어쓰지 않는다. 종료 2분 이내이면서 휴식 시작 전 응답만 새로운 즉시 응답 집계에 포함한다. 2분은 운영상 구분값이며 건강 판정 기준이 아니다. 더 늦은 응답과 시각이 맞지 않는 응답은 별도 집계한다.

휴식 시작 시각은 저장하지만 실제로 눈을 쉬었는지는 측정하지 않는다. 타이머를 일찍 나올 수도 있으며 응답 시각으로 확인할 수 있다. 재부팅·시계 변경에 따른 시각 불일치를 자동으로 건강 변화로 해석하지 않는다.

## 검증 상태

최종 **36개 검사 통과**: JVM 15개, Node 수집기 12개, Android 15 에뮬레이터 9개. Android lint 오류 0개·경고 11개다. 배포 APK는 이전 0.2.0과 서명이 같으며 versionCode는 3이다.

- Android 검사는 동의 취소, 캡처·회전·중지, 사용 후 응답, 휴식 후 별도 응답, 잠금 후 재진입·건너뛰기, 부분 관측 표시, SQLite·보고서 복원 및 이전 기록 호환을 포함한다.
- 에뮬레이터의 실제 화면 캡처에서 생성한 스키마 2 보고서를 별도 테스트 수집기에 전송하고, 재전송이 중복 합산되지 않음을 확인했다. USB 역방향 연결을 사용했으므로 휴대폰 Wi-Fi 경로 검증과는 구분한다.
- 10초 중 507ms만 분석한 입력은 회색 그래프, `0.51 / 10.00초 분석`, 기준 표본 대기 9,000ms 및 종료 꼬리 493ms로 표시됐다. 결과·휴식 응답·부분 분석 화면 이미지를 확인했다.
- 실제 사용자 보고서 4개 세션과 중복 2건을 새 검증기로 재계산해 기존 결과가 유지됨을 확인했다. 테스트 보고서는 사용자 수집 폴더와 분리했다.
- 30분 진단 기록 100개를 직렬화하는 크기 검사와 잘못된 구간 합계·응답 상태 거절 검사를 통과했다.
- 개발 중 저장하지 않는 실시간 필드까지 비교했던 테스트 기대값과 UI 검사 도구의 스크롤 방식을 수정했다. 최종 Android 결과는 `final-instrumentation.log`의 **OK (9 tests)**이며, 초기 실패 로그는 검증 이력으로 남겼다.

## 설치와 다음 테스트

1. 새 APK를 기존 앱 위에 덮어 설치한다. 앱을 삭제하지 않는다.
2. PC 수집기가 실행 중이면 종료하고 `D:\Neurolens2\Start-Collector.cmd`로 다시 실행한다. 실행 중인 이전 서버는 새 형식을 처리하지 못할 수 있다.
3. 재시작한 수집기의 휴대폰 주소를 앱 설정에 다시 저장한다. 연결 키는 실행마다 바뀐다.
4. 쇼츠 재생, 일시정지·재개, 쇼츠 넘김, 앱 전환·복귀, 어두운 화면, 회전·잠금을 각각 확인한다. 어떤 공유 범위를 선택했는지도 별도로 메모한다.
5. 종료 응답을 남기거나 건너뛰고, 필요한 경우 휴식 이후 응답을 남긴 뒤 최근 기록을 전송한다.

## 남은 범위

- 새 실기기 보고서를 받아야 이전의 약 6분 51초 제외 시간을 유발한 상황을 재현·구분할 수 있다. 이번 배포가 그 원인을 이미 해결했다는 의미는 아니다.
- 카메라·피로 점수·스크롤/전환 확정 분류는 추가하지 않았다. 캡처 원본 화면은 저장·전송하지 않는다.
- 30분 실기기 전력·발열과 다른 제조사 확인은 별도다. 표본 처리 시간은 전체 CPU·GPU 비용이나 배터리 소모율이 아니다.
- 대시보드의 브라우저 시각 검증은 이번 환경에서 수행하지 않았다. 집계/API와 스크립트 검증 결과는 아래 최종 로그에 기록한다.
