# 폰에서 보내고 노트북에서 자동 집계하기

0.2.1 업데이트 후에는 PC 수집기를 재시작하고 새 연결 주소를 폰에 저장하세요. 새 수집기는 기존 보고서와 진단·응답 시각이 추가된 스키마 2를 함께 읽습니다.

## 처음 한 번 연결

1. 폰에서 기존 앱을 삭제하지 말고 `artifacts/eyecare-0.2.1-alpha-debug.apk`를 덮어 설치합니다. 같은 debug 서명으로 업데이트되며 기존 기록을 유지합니다.
2. 노트북에서 `Start-Collector.cmd`를 더블클릭합니다. Node.js 20 이상이 필요하며 현재 개발 PC에는 설치되어 있습니다.
3. 실행 창의 **같은 Wi-Fi 휴대폰 주소**를 전체 복사합니다. `http://사설IP:8765/#연결키` 형태입니다. 주소가 여러 개면 휴대폰과 같은 네트워크에 연결된 Wi-Fi/LAN 어댑터 주소를 사용합니다.
4. 폰의 eyecare → 설정 → **집계 연결 주소 설정**에 붙여넣고 저장합니다.
5. 노트북에서 실행 창의 **노트북 주소**를 브라우저로 엽니다.

수집기 창은 켜 두어야 합니다. 다시 실행하면 연결 키가 바뀌므로 앱의 주소도 다시 등록합니다. 연결 키를 포함한 주소를 다른 사람에게 공개하지 마세요. Windows 방화벽 설정은 자동으로 바꾸지 않습니다. 사설 네트워크에서 Node.js 연결을 허용해야 할 수 있으며, 회사·게스트 Wi-Fi에서는 기기 간 통신이 차단될 수 있습니다.

## 테스트 후 전송

앱 **기록 → 기록 선택 → 이 기록 내보내기 → 집계로 보내기**를 누릅니다. 여러 기록은 기록 탭의 **최근 기록 내보내기**를 사용합니다. 최대 최근 100개의 종료된 기록이 대상입니다.

수집기가 받는 즉시 검증·중복 제거·집계를 수행하고 웹 화면은 5초마다 갱신됩니다. 전송이 실패해도 폰의 기록은 남아 있습니다. 같은 보고서를 다시 보내도 중복 합산되지 않습니다.

## 자동 생성되는 결과

| 위치 | 내용 |
|---|---|
| `reports/inbox/*.json` | 받은 원본 보고서 |
| `reports/output/summary.json` | 전체·엔진·기기·콘텐츠별 집계와 오류·충돌 목록 |
| `reports/output/sessions.csv` | 스프레드시트로 열 수 있는 세션별 수치 |

비율은 각 기록의 비율을 단순 평균하지 않고 시간 합계로 가중 계산합니다. 변화가 큰 구간 비율의 분모는 **유효 분석 시간**입니다. 불편감 차이는 전후 모두 응답한 기록만 계산합니다. 임상 피로 점수·인과관계·고유 사용자 수를 산출하지 않습니다.

동일 세션 UUID는 한 번만 반영하며, 응답을 바꾼 높은 수정 번호의 기록이 이전 값을 대체합니다. 낮은 수정 번호가 나중에 도착해도 되돌리지 않습니다. 동일 수정 번호에서 내용이 다르면 해당 세션을 제외하고 충돌을 표시합니다. 잘못된 파일은 오류 목록에 표시하고 다른 유효한 보고서는 계속 집계합니다.

0.1 기록에는 기기 모델·사용 전 응답·누락 사유가 없으므로 미기록으로 표시합니다. 현재 폰의 정보로 과거 기록을 채우지 않습니다. 계정 인증이나 기기 서명으로 진위가 증명되는 연구 데이터는 아니며, 파일이 편집될 수 있다는 전제로 해석해야 합니다.

## 저장·전송 범위

보고서에는 세션 UUID, 측정 시각, 기기 모델·Android API·앱/엔진 버전, 선택한 콘텐츠 종류, 분석 수치, 불편감 응답이 있습니다. 계정·휴대폰 식별자·콘텐츠 URL·화면 이미지·화면 속 텍스트·연결 키는 넣지 않습니다.

앱은 등록한 사설 IPv4의 로컬 수집기로 사용자가 **집계로 보내기**를 누를 때만 전송합니다. 클라우드 자동 업로드·백그라운드 전송은 없습니다. 로컬 HTTP와 실행별 연결 키를 사용하며, 신뢰하는 사설 네트워크에서 쓰는 테스트 도구입니다. 공개 인터넷 서버용 구성은 아닙니다. 연결 키는 인증을 제공하지만 전송 내용을 암호화하지 않습니다.

앱에서 기록을 삭제해도 내보낸 사본은 삭제되지 않습니다. 노트북 집계에서 제거하려면 그 기록을 포함한 `reports/inbox` 원본과 중복 사본을 모두 제거해야 합니다. 수집기가 다시 집계하면 출력 파일에도 반영됩니다. 로그나 브라우저 다운로드로 별도 복사한 파일은 따로 관리합니다.

## 연결이 안 될 때

1. 수집기 창이 실행 중인지, 같은 Wi-Fi인지 확인합니다.
2. 앱에는 **휴대폰 주소**를 넣습니다. 노트북용 `127.0.0.1`은 일반 휴대폰에서 노트북을 가리키지 않습니다.
3. `#` 뒤 연결 키가 빠지지 않았는지, 수집기를 재시작한 뒤 예전 키를 쓰고 있지 않은지 확인합니다.
4. 방화벽·네트워크 정책상 연결할 수 없다면 파일을 노트북으로 옮겨 `reports/inbox`에 넣습니다.

API는 최대 10MB, 보고서당 최대 100개 기록을 받습니다. 전송이 중간에 끊겨 수신 여부를 모르더라도 같은 기록을 재전송할 수 있습니다.
