# EyeCare 0.2.0-alpha 검증과 한계

검증일: 2026-10-08. Windows 로컬 빌드, Android 15 AOSP 에뮬레이터, 로컬 Node.js 수집기를 사용했습니다. 사용자의 실제 휴대폰 기록은 아직 전달받지 않았습니다.

## 변경 범위

- 앱에서 JSON 파일 저장·공유 및 명시적 로컬 수집기 전송.
- 기록 ID와 수정 번호를 이용한 중복 제거·최신 응답 반영.
- 전체·기기·콘텐츠·엔진별 집계, 누락 사유, 전후 응답, CSV 출력.
- 입력 파일 감시와 인증된 HTTP 수신 API.
- 콘텐츠 종류·시작 전 불편감·기기/버전 정보·표본 간격·처리 시간 기록.
- 분석 제외 시간의 구분과 전체 시간 합계 검증, 고정 축 그래프.
- 픽셀 정렬을 1024칸 히스토그램으로 대체하고 입력·이전 프레임 배열 재사용.
- 화면을 전환할 때 스크롤을 처음으로 이동, 전송 완료 상태를 화면에 유지.

## 자동 검증

최종 결과: **28개 테스트 통과, 실패 0개. Android lint 오류 0개·경고 11개**(의존성 업데이트 안내 8개, KTX 사용 권장 3개). APK 서명 검증을 통과했고, 0.1 APK와 서명 인증서가 일치함을 확인했습니다.

| 검사 | 범위 |
|---|---|
| JVM 테스트 13개 | 기존 엔진 9개 + 시간 분할·누락 사유·히스토그램/버퍼 재사용 3개 + 로컬 연결 주소 검증 1개 |
| Android 통합 테스트 6개 | 화면 공유 취소, 화면 꺼짐, 실제 다른 앱 화면 분석/회전/기록/전후 응답/보고서 전송, DB 저장 복원, 0.1 레코드 호환, FileProvider 읽기 권한과 JSON 복원 |
| 수집기 테스트 9개 | 중복·역순 도착·수정 반영, 동률 충돌, JSON 키 순서, 시간 가중 집계, 잘못된 형식 거절, 원본 파일 처리, CSV 수식 방지, HTTP 인증·교차 사이트 요청 차단, 폴더 자동 감시 |

최종 실행 결과와 원본 로그는 `artifacts/v0.2/verification`에 있습니다. Android 통합 전송 검증은 에뮬레이터의 `adb reverse`로 노트북 로컬 수집기에 연결했습니다. 따라서 실제 Wi-Fi·Windows 방화벽 통과까지 검증한 것은 아닙니다.

실제 색상 변화 테스트 앱으로 생성한 기록을 JSON으로 내보내고, 동일 보고서를 재전송한 뒤 앱의 **집계로 보내기** 버튼으로도 전송했습니다. 수집기의 원본 보고서 수와 중복 제외 수가 늘어도 해당 세션은 한 번만 합산됨을 확인했습니다. 시작 전 1·종료 후 2의 응답은 테스트에서 의도적으로 선택한 값이며 사람의 건강 측정 결과가 아닙니다.

## 결과 해석

`valid + sum(excludedMs) = elapsed`를 0.2 보고서의 필수 조건으로 검사합니다. 누락 원인은 관찰 상태에 따른 분류이며 원인의 확정 진단은 아닙니다. 특히 정적인 화면과 프레임 공급 중단은 모두 `missing_frames`에 포함될 수 있습니다. 진행 중 마지막 표본 뒤 시간은 임시로 미관측에 포함되며, 다음 유효 표본 쌍이 도착하면 유효 시간으로 바뀔 수 있습니다.

밝기 대비의 분위수는 히스토그램으로 근사합니다. 각 분위수의 양자화 폭은 1/1023이며 0.1의 정렬 방식과 경계에서 차이가 날 수 있어 엔진 버전을 `exposure-0.2`로 구분했습니다. 평균 절대 변화·큰 변화 판정의 기존 기준은 유지합니다.

보고서의 `meanGlobalChange`는 화면 평균 밝기의 표본 간 절대 변화, `meanChangedArea`는 픽셀 밝기 차이가 0.15 이상인 면적 비율의 시간 가중 평균입니다. 장면 전환·스크롤·빠른 점멸을 확정적으로 분류하지 않습니다. 2fps로 고주파 점멸이나 OLED PWM을 판정할 수 없습니다.

처리 시간은 표본의 픽셀 읽기와 엔진 특징 계산에 걸린 경과 시간입니다. MediaProjection·GPU·OS 전체 비용이나 CPU 사용률을 뜻하지 않습니다. 정렬·배열 할당을 줄였지만, 배터리 절감률·실기기 발열 개선 수치는 아직 측정하지 않았습니다.

## 전송 보안과 동작

- 앱은 사용자 지정 사설 IPv4와 포트, 48자리 실행별 키를 검사하며 리다이렉트를 따라가지 않습니다.
- 수집기는 Bearer 키를 확인하고 브라우저의 다른 Origin 요청을 거부합니다. 파일 경로는 수신 내용의 SHA-256으로 만들며 업로드 파일명을 경로로 사용하지 않습니다.
- 최대 10MB·보고서당 100개 기록, 시간·구간 합계·형식·수정 번호를 검사합니다. 보고서의 진위나 측정자의 신원을 인증하는 기능은 없습니다.
- 로컬 HTTP이므로 전송 내용은 암호화되지 않습니다. 사설 테스트 네트워크용이며 공개 서버 배포에는 별도 TLS·사용자 인증·보존 정책이 필요합니다.
- 네트워크는 사용자가 보내기를 누를 때만 사용합니다. 화면 캡처 이미지는 보고서에 넣지 않습니다. 카메라·마이크 권한이 없습니다.

## 남은 검증

1. 실제 휴대폰에서 APK 덮어 설치, 이전 기록 내보내기, 사설 Wi-Fi 직접 전송, 제조사별 파일 저장·공유 대상 확인.
2. Android 버전·기기별 30분 배터리·발열·표본 누락 비교.
3. 밝기·장면 전환·스크롤·어두운 정상 영상의 기준 콘텐츠를 통한 특징 보정.
4. 사용 전후 응답을 반복 수집해 설명 가능한 관계를 탐색. 현재 시간 기준 알림을 임의의 피로 점수 기반 알림으로 바꾸지 않음.
5. 대시보드의 실제 브라우저 렌더링·모바일 배치. 이번 실행에서는 브라우저 도구가 로컬 URL 접근을 권한 거절로 차단해 육안 검증하지 못했습니다. HTTP/API·집계 계산·스크립트 문법은 별도로 확인했습니다.

파일 저장은 Android CreateDocument로 구현했으며, 자동 검사에서는 보고서 생성·FileProvider 공유와 직접 전송을 검증했습니다. 제조사별 문서 선택기에서 최종 저장까지의 조작은 후속 실기기 확인 항목입니다.
