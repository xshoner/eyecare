# 0.8.0 진단·성능 기준선과 기기 검증 절차

## 변경 전 확인값 (0.7.3-alpha 소스와 APK)

| 항목 | 확인한 기준선 | 0.8.0의 조치 |
|---|---|---|
| 화면 | 긴 변 256px, 500ms 미만 프레임 제외(최대 약 2fps), 재사용 FloatArray/IntArray | 중등도 열 상태에서 화면만 최대 약 1fps, 심한 상태에서 분석 일시 중지 |
| 전면 카메라 | 640×480에 가장 가까운 YUV 스트림, 처리 FPS 제한 없음, `acquireLatestImage`, 단일 HandlerThread/VIDEO 추론 | 눈 경로 FPS·해상도 유지; YUV 픽셀·Bitmap 재사용, 회전을 같은 버퍼에 적용 |
| 눈 저장 | 매 카메라 분석 프레임마다 SQLite 행 1개/트랜잭션, 최근 5분 관측 객체에 랜드마크 등도 보유 | 최대 4프레임 또는 250ms를 한 트랜잭션으로 저장하고 정상 종료·화면 꺼짐 때 플러시; 점수용 최근 메모리에서는 중복 랜드마크 배열을 제외; 거리 요약은 최대 5fps만 사용, 눈 깜박임 경로는 유지 |
| 기초 APK | 65,396,240 bytes, ARM64·armeabi-v7a 포함 | `release` 구성에서 디버그 전용 Compose tooling을 제외하고 기존 디버그 인증서로 서명해 업데이트 호환성을 유지. 최종 크기·서명·모델·ABI를 재검증 |
| 주요 자산 | Face Landmarker 3,758,596 bytes; MediaPipe JNI ARM64 14,365,544 bytes, v7a 10,115,520 bytes | 검증 없이 모델·ABI 삭제 없음 |

이 환경에는 Android 실기기가 없어서 변경 전후 CPU%, 실제 FPS, 추론 시간, 배터리 소모, 발열, 거리 오차의 관측값은 없다. 앱 진단 화면의 전달 FPS·프레임 간격·처리 시간·표본 나이·거리 coverage/지터·결측 이유·열 severity/headroom으로 기기에서 수집할 수 있다. Headroom은 °C가 아니다.

## 거리·눈 반응 기기 검사

같은 기기에서 화면 밝기, 충전 상태, 실내 온도를 고정한다. 눈과 **전면 카메라** 사이를 자로 30cm 맞춰 앱의 30cm 보정을 한 뒤 20/25/30/40/50/60cm 각각 1분 관찰한다. 밝음과 어둠, 안경 유무, 정면과 좌·우 고개 각도 조건을 따로 반복한다. 각 조건에서 실제 거리, 앱 추정 중앙값, 절대 오차, coverage, 지터, 결측 이유, 눈 검출률, 전달 FPS와 처리 시간을 기록한다. 보정에 사용한 30cm 조건은 독립 검증 결과에서 제외한다. 기기별 오차 기준은 측정 전에 정하고, 실패/결측을 0cm 또는 정상으로 대체하지 않는다.

눈 깜박임은 동의받은 로컬 기준 영상/수동 주석과 같은 시간축으로 대조한다. 15/20/30fps 후보를 **동일 원본**에서 가상 다운샘플해 완결된 깜박임 precision·recall, 짧은 눈감김 누락, 얼굴 소실 후 오인, 처리 시간·coverage를 비교한다. 현재 앱의 눈 FPS를 선제적으로 낮추지 않는다. 임상 정확도나 배터리 개선은 이 기기 비교 전까지 미검증이다.

## 보정 및 휴식 안내

개인 보정 평가는 산식 버전별로 시간순 보고서의 **당시 이전 수신 응답**만 학습한다. 첫 응답은 후행 정답으로만 쓰고, 나중 수정은 과거 예측으로 되돌려 넣지 않는다. 동일 홀드아웃 보고서에서 원점수와 개인 참고값의 NRS×10 대비 평균 절대 차이를 계산한다. 평가 보고서 5개 미만은 ‘검증 표본 부족’으로 표시한다. NRS와 점수 차이는 의학적 정확도가 아니다.

휴식 카드는 기본 OFF. 사용자가 켜고 시스템 권한을 허용한 경우 점수 50 이상·유효 근거가 2분 지속될 때 작은 비차단 카드로 나타난다. 기본 재알림 20분, 미루기 10분, 닫기·전체 OFF가 있다. 권한이 없으면 일반 알림으로만 안내한다. 화면 잠금·공유 중단·측정 종료·심한 열 상태에서 제거한다. 임계값과 시간은 검증 전 가설이며 오탐·놓침을 별도 기록해야 한다.

## 장시간·열 비교

0.7.3과 0.8.0을 동일 기기·조건에서 각 30분/60분 측정하고 전달 FPS 분포, 프레임 간격, 처리 시간, 눈 검출·거리 coverage, 발열 severity/headroom, 배터리 % 변화, 앱 메모리, 알림 오탐을 비교한다. 회전, 카메라 점유, 화면 공유 중단, 반복 시작/종료, 네트워크 오프라인 재시도, 프로세스 재시작을 각각 점검한다. 심한 열 상태에서는 분석을 멈추고 점수를 미측정으로 표시하며, 낮은 열 상태가 30초 지속돼야 재개한다. 열 또는 정확도 개선은 실제 측정 없이 보장하지 않는다.

## 이번 빌드 검증 결과

눈 깜빡임은 유효 연속 프레임 간격의 중앙값이 150ms를 넘으면 0회로 단정하지 않고 `insufficient_temporal_sampling`으로 표시한다. 짧은 거리 진단은 초깃값·사용자 자 측정과 비교하는 프로토콜이며 실측 오차 결과는 아직 없다.

2026-10-11 로컬 검증: Android 단위 테스트 79개 통과, `lintDebug`, `assembleDebug`, `assembleRelease`, `assembleDebugAndroidTest` 통과. lint XML에는 경고 25개와 힌트 1개가 있으며 빌드를 막는 오류는 없다. 계측 테스트 APK는 컴파일했지만 연결된 Android 기기가 없어 실행하지 못했다. 실제 overlay 권한·백그라운드 제약, 거리/깜빡임 정확도, 실기기 FPS·CPU·열·전력은 측정하지 않았다.

새 APK `eyecare-0.8.0-alpha-phone.apk`는 56,517,975 bytes, SHA-256 `1D889D6E498D7A121BAEBEF0C8EAAD3BF8B02647AAA14BF4AF180AEDBD63FEB0`이다. 0.7.3 APK 65,396,240 bytes 대비 8,878,265 bytes(13.58%) 작다. `versionCode=19`, `versionName=0.8.0-alpha`; 기존 APK와 서명 인증서 SHA-256이 일치한다. Face Landmarker 자산과 `arm64-v8a`·`armeabi-v7a` MediaPipe JNI가 모두 포함된다.

합성 API 회귀(2026-10-11): 익명 가입·갱신, 동의 후 관측 저장, 중복 409와 본인 조회, 공개 anon·타인 조회 차단, 거리 집계 필드 저장·조회, NRS 응답 2건 append와 중복 차단·승인된 브라우저 읽기·타인 쓰기 거부를 확인했다. 테스트 행은 "synthetic-test-*" 산식 버전으로 표시해 서버에 유지했다. 이 검사는 직접 REST 합성 요청이며 Android 실기기 WorkManager 전송 검사는 아니다. 거리 연속 보고 구간의 시간 가중치가 중복되지 않는 단위 테스트도 추가했다.

## 갤럭시 S25+ 게임 발열 A/B 확인

사용자 관찰은 게임 시작 약 10분 뒤 발열이며 원인은 미확정이다. 같은 게임의 같은 반복 가능한 장면/경로와 그래픽 설정·주사율·네트워크·수동 화면 밝기·음량·케이스·주변 온도를 유지한다. 충전하지 않고, 다른 백그라운드 작업/화면 녹화를 끈다. 배터리 잔량과 시작 열 상태를 비슷하게 맞춘다. A는 EyeCare 측정 서비스를 완전히 종료한 게임 단독, B는 같은 게임에 EyeCare 측정(전면 카메라와 MediaProjection)을 더한 상태다. 각 회차 사이에 휴대폰을 충분히 식혀 시작 열 상태가 같아진 뒤, A–B–B–A 순서로 각 20~30분씩 실행한다. 위험할 정도로 뜨겁거나 OS 열 경고가 나타나면 즉시 종료한다.

0·5·10·15·20분(가능하면 30분)에 같은 위치의 표면 온도(같은 외부 온도계가 있을 때), Android thermal status(ADB 등 같은 방법), 게임 FPS/끊김, 시작·종료 배터리 %, 주변 온도를 기록한다. B에서는 `홈 → 측정 상태 자세히`의 전달 FPS·처리 시간·거리 coverage·열 상태/headroom·분석 일시 중지를 함께 기록한다. Headroom은 °C가 아니며 표면 온도와 바꿔 쓰지 않는다. 단독 게임도 뜨거워지면 게임 자체 부하를 고려하고, B에서 반복적으로 상승이 빨라지거나 FPS가 떨어지면 카메라 추론·MediaProjection의 추가 CPU/GPU/메모리 대역폭 부담을 의심한다. 장면 차이·열 누적·네트워크 변동이 있으면 결론을 보류하고 반복한다. 현재 실제 A/B 계측은 없다.

현재 앱은 열 상태를 10초마다 읽고 MODERATE 이상에서는 화면 분석을 약 2fps에서 약 1fps로 줄인다. SEVERE 이상에서는 전면 카메라를 멈추고 화면 프레임 분석을 건너뛰며 점수를 미측정으로 표시한다. LIGHT 이하가 30초 이어지면 재개한다. 게임과 함께 실행해도 카메라 FPS를 평상시 임의로 낮추지 않으므로, 위 비교에서 추가 발열이 뚜렷한지와 실제 깜빡임 표본 품질을 먼저 확인해야 한다. 이 제어가 실제 발열을 줄였다는 측정 결과는 없다.
