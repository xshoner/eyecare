# 0.12.0-alpha: 눈 컨디션 점수 표시 전환 (높을수록 양호)

## 변경 내용

- 사용자에게 보이는 점수를 **눈 컨디션 = 100 − 저장 부담 점수**로 바꿨습니다. 100에 가까울수록 양호하고, 낮을수록 주의·위험입니다.
- 구간은 기존 부담 구간과 정확히 1:1로 대응하며, 새 임계값을 추가하지 않았습니다.

| 눈 컨디션 | 표시 | 기존 부담 점수 | 비고 |
|---:|---|---:|---|
| 76–100 | 양호 | 0–24 | |
| 51–75 | 주의 | 25–49 | |
| 0–50 | 위험 | 50–100 | 휴식 알림 시작 구간(부담 ≥50)과 같음 |

- 근거가 부족한 부분 추정(`PersonalTrend.comparable == false`)은 점수가 높아도 **양호로 표시하지 않고** 회색 "근거 부족·판정 보류"로 표시합니다. 0.11 산식은 빠진 영역을 정규화하지 않으므로, 이를 반전하면 입력이 적을수록 점수가 높게 나옵니다. 이 오해를 막으려는 조치입니다.
- 적용 위치는 홈 점수 링, 리포트 상세·목록, 추이 차트(축·색 구간 반전), 측정 중 카드, 오늘 누적 문구("오늘의 눈 컨디션"), 개인 기준 참고값, 이전 대비 문구("N점 올라 좋아짐"), 리포트 알림, 휴식 오버레이·알림, 설정 안내문입니다.
- 공통 로직은 `engine/EyeCondition.kt` 한 곳에 있습니다.

## 바꾸지 않은 것

- 저장 필드 `score`, JSON 내보내기, CSV, Supabase 연구 업로드는 계속 **부담 점수(높을수록 부담)**입니다. 그래서 과거 기록·서버 스키마·산식 버전 `efs-exposure-0.11`과의 연속성이 유지됩니다.
- 휴식 알림 정책(`RestAlertPolicy`), 개인 보정, NRS 비교(MAE)는 내부적으로 부담 점수 기준 그대로입니다. MAE는 반전해도 값이 같습니다.
- 웹 대시보드(`xshoner/eyecare`)는 아직 부담 점수로 표시합니다. 일관성을 위해 같은 표시 변환이 필요합니다.
