# EyeCare 자연 사용 벤치마크 v0.2

작성 2026-10-10 · 파일럿용 설계안 · 성능 달성/임상 검증 선언 아님

[현재 PRD](../../EyeCare_PASSIVE_PRD_2026-10-10.md) · [엔진](../../EyeCare_FATIGUE_DESIGN_2026-10-10.md) · [구현 계획](IMPLEMENTATION_PLAN.md) · [JSON 계약](passive-spec-v0.2.json)

**v0.1 대체:** 소비자에게 보정 표적·얼굴/거리 정렬·100초 표준 과제를 요구하지 않는다. 기본 벤치마크도 30분 자연 사용이다. 내부의 센서 기준 계측은 측정 오류 확인을 위한 연구이며 제품 절차로 추가하지 않는다.

## 1. 무엇을 증명할 것인가

1. 사용자가 정렬하지 않아도 초기/약 30분 뒤의 눈 관측을 얼마나 확보하는가.
2. 조건이 나빠질 때 틀린 숫자를 내는 대신 일부 특징/넓은 오차/보류로 처리하는가.
3. 동일 관측 범위에서 시간·화면 모델보다 눈 반응이 피로 추정에 도움이 되는가.
4. rPPG·거리 특징이 전력과 복잡도를 감수할 추가 가치를 가지는가.
5. 장시간 자동 케어의 전력·열·게임/영상 영향과 실제 알림의 사용성이 허용되는가.

넓게 측정하는 목표와 오차 허용을 함께 평가한다. 높은 정확도만 보여주려고 어둡거나 누운 세션을 분모에서 제외하지 않는다. 미관측 눈에 임의 값을 넣어 확보율을 높이지 않는다.

## 2. 분모와 관측률

| 지표 | 분모 | 분자/정의 |
|---|---|---|
| 시작 성공률 | 연구에서 케어 시작을 요청한 모든 세션 | 시스템 동의 후 실제 센서 활성 |
| 케어 활성률 | 연구에서 의도한 30분 사용 시간 | 유효 화면 공유가 살아 있던 시간 |
| 카메라 개방률 | 같은 화면 사용 시간 | 실제 camera open 시간; NN 실행률과 별도 |
| 눈 관측률 | 카메라 개방 시간 | 해당 눈 특징이 유효한 시간 |
| 전후 확보율 | 의도한 30분 자연 사용 세션 전체 | 초기/종료 유효 눈 창이 모두 존재 |
| 활성 구간 전후 확보율 | 적법한 공유가 지속된 30분 구간 | 같은 전후 조건. 위 전체 확보율과 함께 제시 |
| 피로 점수 출력률 | 30분 사용 세션 전체 | 각 근거 모드의 숫자 출력. 보류는 분모에 남김 |
| rPPG 출력률 | 의도한 모든 pulse 관측 기회 | 기준 센서와 비교 가능한 HR 출력 |

미동의, 카메라 경쟁, 얼굴 없음, 가림, 저조도, 잠금으로 공유 종료, 서비스 죽음, 예산으로 미실행은 서로 다른 실패 사유다. 보호된/어두운 화면은 화면 품질 실패로 표시하며 눈 관측 여부와 혼동하지 않는다. 시스템 동의를 거부한 사례도 시작 경험에 포함한다.

측정 가능 조건의 feature-error와 전체 세션의 coverage를 같이 그린다. 모델 비교는 공통 평가 세션과 실제 전체 출력 범위 모두에서 한다. coverage를 낮춰 MAE가 좋아졌다면 그 비용을 공개한다.

## 3. 자연 사용 30분 절차

제품과 같은 앱을 사용하며 얼굴을 카메라에 맞추거나 특정 표적을 보게 하지 않는다. 초반/끝 연구 응답 이외에는 앱 이동·쇼츠·영상·독서·게임을 자연스럽게 한다. 콘텐츠 자극을 높이려고 인위적 빠른 점멸을 만들지 않는다.

| 시점 | 제품 관측 | 연구 라벨 |
|---|---|---|
| 시작 직전 | 사용자 케어 시작, 플랫폼 동의. 정렬 없음 | 눈 피로 NRS 0~10, 건조감/불편감/졸림 각각 분리 |
| 사용 0~3분 | 자연 초기 60초 관측, 실패 시 5분까지 재시도 | 정확한 응답/관측 시각 저장 |
| 5·10·15·20·25분 | 기본 45초 관측 + 예산 안 트리거 | 개입 없는 사용, 원본 clip은 연구 동의자만 |
| 27~30분 | 종료 60초 관측 | 30분 사용 직후 NRS·분리 증상, 실제 앱/활동 회고 |
| 30~33분 | 종료 관측 실패 시 재시도 후보 | 늦은 관측/응답을 구별, 실제 경과 표시 |
| 선택 후속 | 자연 휴식 및 다음 사용 기록 | 5~10분 후 추가 응답 후보. 휴식의 효과/치료 효능으로 단정하지 않음 |

초기 응답 자체를 최종 제품 입력으로 사용하지 않는다. 30분 변화 정답은 끝 NRS−초기 NRS이며 초기 NRS를 의무 입력으로 쓰지 않는 모델과 비교한다. 초기 응답을 쓰는 연구 보조 모델은 제품 모델과 별도 결과다.

종료 응답이 실제로 늦으면 그 시각과 이후 사용량을 기록한다. paired-label 핵심 분석은 30분±3분 응답, 초기 눈 관측 0~5분, 종료 27~33분인 자료부터 수행한다. 지연·생략·중간 종료 기록을 삭제하지 않고 라벨 없음으로 남긴다. 연구 라벨을 정상 사용의 필수 입력으로 만들지 않는다.

전후 창은 각각 eye valid ≥30초, 관측 창 내 유효 비율 ≥50%가 초기 후보다. 비교 가능한 특징 마스크를 사용한다. 이것은 임상 기준이 아니라 파일럿 관측 규칙이다. 자세가 다른 두 창에서 수학적 보정의 지지 범위가 없으면 해당 Δfeature를 보류한다.

## 4. 조건 매트릭스

모든 조합을 한 사람에게 요구하지 않는다. 균형 잡힌 반복/불완전 블록으로 조건을 배분하고 실제 자연 사용 분포의 관측 자료를 함께 수집한다.

| 축 | 포함할 조건 | 기록 |
|---|---|---|
| 자세 | 앉기·기대기·옆으로/누워 보기·하방 시선·수평/수직 회전 | 실제 yaw/pitch/roll·얼굴 위치, 지지 범위 |
| 거리 | 자연 가까운/중간/먼 사용, 중간 변화 | 연구 기준 거리, 사용자 정렬 없음 |
| 조도 | <5 / 5~50 / 50~300 / ≥300lux, 역광·측면광 | 광학 계측과 폰 lux, 가림·센서 없음 |
| 콘텐츠 | 쇼츠·긴 영상·게임·뉴스/긴 글·혼합 | 앱 범주와 실제 연구 라벨, 추정/정답 구별 |
| 화면 | 자동/고정 밝기·야간 색조·검은 구간·보호 화면 | 디지털 luma·밝기 설정·이벤트 |
| 사람 | 눈 모양·안경·반사·피부톤·기존 피로/졸림 차이 | 연구 동의하의 특성, 세부 집단 수 |
| 기기 | 현재 SM-S936N + 다른 제조사/성능 2종 이상 | OS·카메라 파라미터·실제 FPS·센서 유무 |
| 중단 | 잠금·전화·카메라 앱·화상통화·권한 철회·죽음 | 복구 가능 범위, 부분 결과, 종료 상태 |

lux 구간은 실험 층이며 피로 위험 경계값이 아니다. 수면/시각 상태는 자기보고 문맥이지 앱이 자동 진단한 값이 아니다. 피부톤·눈 모양별 모델 실패를 계측하되 해당 특성 입력을 사용자에게 필수로 요구하지 않는다.

한쪽 눈만 관측 가능한 경우를 별도 평가한다. 얼굴이 화면 밖으로 완전히 나간 조건에서는 눈 반응 측정이 불가능하다는 결과를 그대로 보고한다. 모델로 관측을 만들어내지 않는다.

## 5. 단계와 표본 계획

| 단계 | 초기 규모 | 목적 / 산출물 |
|---|---|---|
| L0 플랫폼·자원 | 제조사 3종, 반복 60분 사용/중단 시나리오 | 합법적 수명·간헐 재획득·전력·PSS, 지원 범위 |
| L1 센서 타당성 | 성인 12명, 각 2개 이상의 자연 사용 조건 | 눈 라벨·거리/HR 기준, 조건별 실패와 시간 오류 |
| L2 반복/라벨 파일럿 | 성인 30명×4회×30분 가정 | 약 60시간 사용, 전후 확보율·라벨 분포·특징 반복성 |
| L3 모델 연구 | 성인 120명×2회×30분 초기 계획 | 약 120시간, train 60명 / validation 20명 / 새 locked test 40명 |
| L4 외부/전향 사용 | 별도 최소 20명 및 새 기기 | 자유 사용, 알림 적정성, 개인화 미래 방문 |
 
참가자 모집과 통계 검토 전의 규모 가정이다. 실제 변화량 분포·반복 상관·결측률로 공식 표본 수와 조건별 최소 사례를 재산정한다. L1/L2는 규칙 탐색 자료이며 잠금 시험에 재사용하지 않는다. 청소년 모델은 별도 계획을 세운다.

카메라 프레임 수를 표본 수처럼 제시하지 않는다. 피부톤·야간·누움 등 집단당 세션 수가 적으면 그 집단의 일반화 승인을 보류한다. N=120만으로 모든 조건이 검증됐다고 주장하지 않는다.

## 6. 내부 기준 계측

### 눈/시선

연구에 별도 동의한 카메라 clip에서 좌우 개방, 깜빡임 시작/최저점/끝, 오래 감김, 가림·누락, 방향 변화 후보를 2인 라벨링한다. 불일치는 합의 및 평가자 간 일치도와 함께 보고한다. 같은 영상으로 라벨/추론하는 경우 측정 해상도 한계를 기록한다.

깜빡임 지속시간의 엄밀한 평가가 필요하면 일부 자연 자세에서 시간 동기화된 고속 참조 카메라를 사용한다. 참여자가 소비자 앱의 정렬 과제를 수행하게 하지 않는다. 참조 장비 때문에 자세가 제한됐다면 별도의 제한 조건 결과로 표시한다.

보정 없는 시선 첫 평가는 눈/머리 방향 변화의 안정 proxy다. 정밀 응시점/특정 콘텐츠 응시 평가를 기본 피로 승격 조건으로 두지 않는다. 참조 eye tracker를 쓰는 하위 연구는 내부 연구이며 소비자 보정 절차로 이전하지 않는다.

### 맥박

자연 사용 중 동기화된 접촉 PPG/ECG HR를 참조한다. 안정된 피부 신호와 움직임·화면 조명 혼입 조건을 따로 비교한다. 접촉 손가락 PPG의 정확도를 전면 얼굴 rPPG 정확도로 이전하지 않는다. HRV는 별도의 beat timing 연구를 통과하기 전 비활성이다.

pulse 없음/정지 영상/주기적인 화면 반사 같은 음성 대조를 포함한다. 실제 맥박과 조명 변화가 같은 주파수인 경우를 포함하고, 출력률을 높이기 위한 잘못된 수용을 점검한다.

### 거리·환경

내부 depth/광학 거리 계측과 얼굴 자세를 함께 기록한다. 정면 거리만 맞는 모델의 누운 자세 일반화를 승인하지 않는다. 거리 범주와 같은 사람 내 방향 변화를 먼저 평가한다. 시력 정답/시력 점수는 이번 모델에 없다.

조도는 폰 센서와 외부 기준을 비교하고 센서 가림·화면 빛·역광을 구별한다. 실내/실외 정답은 연구 기록에서 확보할 수 있으나 제품은 confidence 없이 확정하지 않는다.

## 7. 초기 목표 — 파일럿 후 잠금

아래는 달성 사실·의학적 경계값이 아니다. 파일럿 후 특징 해상도/지원 범위와 정답 반복성을 보고 수정하며, locked test를 본 뒤 목표를 낮추지 않는다.

| 항목 | 초기 목표 | 실패 시 |
|---|---|---|
| 정렬/검사 요구 | 정상 사용 0회 | UX 방향 위반, 재설계 |
| 전후 확보율 | 활성 30분 구간 전체의 ≥70% 목표 | 자세/빛/예산별 실패를 분석, 자동 샘플링/특징 개선 |
| 눈 이벤트 | 유효 조건 blink precision/recall 각각 ≥0.85, F1 ≥0.85 | 빈도/이벤트 범위 축소; 관측률도 병기 |
| blink 지속시간 | 고속 기준 부분 자료 MAE ≤80ms 목표 | 해당 조건의 지속시간 특징 제외 |
| 감김 비율 | 수동 기준 MAE ≤8%p 목표 | 폐쇄/품질/하방 시선 보정 개선 |
| 시선 proxy | 사람 라벨의 방향 안정 여부 macro F1 ≥0.75 | 정확한 응시점 주장 없이 특징 보류/재설계 |
| HR 보조 | 출력된 창 MAE ≤5bpm, P95 ≤10bpm; 음성 대조 오수용 ≤5% | pulse 제외/품질 경계 수정, 기본 케어는 유지 |
| 피로 NRS | 현재/Δ NRS MAE 각각 ≤1.5 초기 목표 | 라벨/특징/목표 범위를 재검토 |
| 눈 반응 추가 가치 | M2+가 같은 세션의 M1 대비 현재 또는 Δ MAE ≥10% 감소 목표 | 피로 수치 활성화 보류, 유용한 관측 카드 검토 |
| 예측 구간 | 목표 90% 구간의 실제 포함률 및 폭 보고 | 불확실성 보정, 넓은 구간은 점수 보류 |
| 자원 | 추가 PSS ≤80MiB/총 ≤180MiB, 수치 버퍼 ≤20MiB | 분해 측정·저해상/일정 조정, 저성능 지원 범위 재검토 |
| 전력 | 대조 대비 중앙값 ≤5%p/시간 목표 | duty cycle/FGS 경로/특징 비용 조정 |

기본 카메라 일정은 60+5×45+60=345초/30분, 재시도/트리거 포함 rolling 30분 camera-open ≤540초 목표다. 서비스를 유지한 채 카메라를 해제할 수 없으면 실제 개방률과 전력을 그대로 보고하며 이 예산 달성으로 처리하지 않는다.

incomplete blink와 거리 범주는 L2에서 기준 라벨 일치도/오차를 보고 잠금 목표를 정한다. rPPG의 광범위 출력률 70%를 필수로 요구하지 않는다. 안정된 subset에서만 작동해도 모델 효용이 있으면 채택 후보가 될 수 있으나 전체 자료의 효과를 함께 보고한다.

## 8. 모델 평가와 오류 분석

- 모든 분할은 사람 단위. 같은 사람의 clip/창/방문을 무작위로 나눠 정확도를 높이지 않음.
- 특징 선택·보정·정규화·임계값·보류 정책은 train/validation에서만 결정.
- M0 시간/문맥, M1 화면/조도, M2 눈, M3 방향/거리, M4 HR의 같은 후보군 비교 및 leave-one-signal-out.
- 하나의 최종 모델을 모달리티 누락 상태로 평가. 눈 없음, HR 없음, 조도 없음, 한쪽 눈, 시작 창 없음, 새 기기 등 실제 조합 포함.
- 현재 NRS/Δ NRS MAE·편향·95% CI, 피로 증가 판별과 저신뢰 보류, 출력률-오차 곡선을 보고.
- 졸림·과제·눈 건조감·초기 피로별 오차. 단순히 시간이 길어졌다는 이유만으로 Δ를 예측하는 오류 확인.
- confidence interval은 사람 단위 bootstrap 후보. 작은 집단의 단일 숫자에 과도한 확신을 부여하지 않음.
- 개인화는 과거 기록만 사용하고 별도 미래 방문에 평가. 새로운 사용자는 모집단 prior로 평가.
- 카메라 관측이 잘되는 사람이 쉬운 정답만 갖는지 선택 편향을 확인. 동일 출력 범위와 실제 서비스 전체 효용을 같이 비교.

점수 0~100 MAE만 보고하지 않고 원래 NRS 단위와 실제 라벨 분포를 함께 보고한다. 90% 구간이 지나치게 넓으면 잘 보정된 숫자여도 소비자 점수를 보류한다. 임계값은 사용자의 알림 부담과 피로 증가 검출의 비용을 validation에서 비교해 결정한다.

## 9. 실기기·알림 평가

L0/L1에서 같은 폰·같은 콘텐츠·밝기·통신 조건의 케어 OFF/화면만/화면+눈/화면+눈+HR를 반복 비교한다. 60분 전력 측정에는 charge counter 또는 외부 계측을 우선하며 배터리 %만 썼다면 해상도 한계를 명시한다. CPU/GPU/native PSS, 카메라 개방 시간, 실제 FPS, UI/game jank, 열 단계, 서비스 죽음을 기록한다.

추가 전력은 처리 시간 합으로 추정하지 않는다. 최고 성능 폰 한 대로 저가 폰의 소비전력을 주장하지 않는다. OS29 최소 범위와 API34~36의 FGS/권한 차이를 실제 기기 범위에 맞춰 보고한다.

전향 사용에서는 알림을 유용하다고 평가한 비율, 즉시/나중에 휴식, 오탐 신고, 알림 끄기, 권한 철회, 재사용을 측정한다. 앱 종료를 강제하거나 알림을 늘려 효과를 만드는 실험은 하지 않는다. time-alert와 fatigue-alert의 결과를 구별한다.

## 10. 고정·승격·보관

데이터 snapshot/동의 범위, 참가자 분할 hash, 전처리/특징 버전, 모델 hash, 기기/조건 지원표, 품질/보류/알림 정책을 잠금 시험 전에 고정한다. 시험 실패 시 재개발하고 새 독립 시험을 확보한다.

알파는 관측 사실·시간 알림, 모델은 그림자 실행. 피로 점수 승격은 눈 반응의 가치, 전후 확보율, 누락/조건별 오차, 자원, 전향 사용성의 공동 검토 후 한다. pulse 기여가 없다고 전체 앱 개발을 막지 않고 기본 엔진에서 제외한다.

연구 clip은 기본 30일 보존 가정에서 분석 일정·동의에 맞춰 확정하고, 모델 학습용 수치 보존은 별도 기간을 동의서에 명시한다. 원본 화면·얼굴을 사용자 기본 보고서로 자동 전송하지 않는다. 연구 수집과 실제 사용자 inbox를 구별한다.
