# EyeCare 눈 피로 알고리즘 단계별 구현 계획

설계 초안 v0.1 · 2026-10-10

첫 개발 목표는 현재 화면 분석 앱에 **표준 화면을 보는 전후 검사, 눈·시선·rPPG 관측, 품질과 응답이 연결된 보고서**를 추가하는 것이다. 피로 모델은 센서 검증과 라벨을 확보한 뒤 적용한다. 구현 단계마다 결과를 검토하고 다음 단계로 넘어간다.

설계 기준: [전체 설계](../../EyeCare_FATIGUE_DESIGN_2026-10-10.md), [벤치마크](BENCHMARK_PROTOCOL.md), [재사용 자산](REFERENCE_AUDIT.md), [구조화한 초안](benchmark-spec-v0.1.json).

## 1 단계와 일정

일정은 Android 담당 1명, CV·신호 담당 1명, 제품·연구 운영 일부 참여, 안과·통계 자문과 기준 센서 확보를 가정한다. 1인 진행은 작업량에 맞춰 기간을 늘린다. 모집과 외부 검증은 개발 기간과 별도로 진행한다.

| 단계 | 예상 기간 | 작업 | 통과 조건 |
|---|---|---|---|
| **G0 설계 확정** | 현재~1주 | 목표·모드·특징·시계·라벨·데이터 계약·잠정 기준 검토 | 참조 자산 고정, 연구 목적과 기준 장비·동의 범위·분할 계획 확정 |
| **G1 카메라 기술 검증** | 1~2주 | 전면 카메라·실측 FPS·랜드마크·RGB·카운터·시간 정렬, 동시 서비스 가능성 검증 | 대표 폰 3종에서 품질·성능 로그, 닫힌 눈과 검출 실패 구별, 지원 모드 판정 |
| **G2 센서 엔진 이전** | 2~4주 | 눈 이벤트·시선 수학·POS/CHROM 이전, 재생 입력과 공통 수치 검증 | 수동 라벨·공개/기준 센서 비교, 기존 화면 회귀 유지, 실제 오류·출력 범위 보고 |
| **G3 연구 앱 통합** | 4~6주 | 약 100초 표준 검사, PRE/POST/RECOVERY 연결, 저장·내보내기·집계 | 검사 중단·복귀·결측·카메라 거절·기존 보고서 호환 확인 |
| **G4 반복성 파일럿** | 6~10주 | 30명 반복 검사, 응답·무부하·자극·혼동 요인 평가 | 특징별 신뢰도, 피로 응답 분포, 표본·시간·조건 확정 |
| **G5 피로 모델** | 10주 이후 | 규제 회귀부터 M0~M4 비교, 별도 결측 조합 모델, 그림자 평가 | 독립 사람·시간 분리·보정·기여도·출력 범위 기준 통과 |
| **G6 앱 점수 적용** | G5 이후 | 승인한 모델·조건만 활성화, 결과 근거·부분 측정·보류 표시 | 제한 배포와 전향 평가, 모델 카드·지원 기기·롤백 검증 |

**6주 전후의 연구 앱은 관측 수치를 제공하는 목표다. 피로 추정 정확도 검증 완료 일정은 모집·응답 분포·기준 센서 평가 결과에 달린다.** 구현 완료를 모델 검증 완료와 구별한다.

기준 센서 미확보는 관측 엔진 개발을 막지 않는다. 다만 실제 폰 rPPG 정확도 승인과 피로 모델의 해당 입력 검증은 기준 확보 후 진행한다.

## 3 G1 플랫폼 검증의 구체 과제

### 모드 A와 B

CameraX의 전면 `ImageAnalysis`를 앱 검사 수명에 연결한다. 참조 화면·카메라 회전·해상도·메타데이터를 기록한다. 시작은 1280×720 요청 또는 기기가 지원하는 유사 해상도, 추론 입력은 약 640px 긴 변을 후보로 한다. 눈 ROI는 원본 해상도에서 따로 확보해 작은 눈의 정보를 보존한다. 요청 해상도와 실제 해상도를 구별한다.

원래 YUV/RGB에서 피부 ROI 표본을 먼저 추출한다. 색 공간·full/limited range·stride·회전을 알려진 이미지 입력으로 확인한다. 눈/랜드마크용 영상 보정이 rPPG 입력에 섞이지 않게 분리한다.

추론·RGB 처리·UI 갱신을 분리하되 프레임 ID와 실제 시각을 유지한다. 미처리 프레임을 세고, `KEEP_ONLY_LATEST`로 생긴 누락을 보간된 생체 신호로 숨기지 않는다. 오래된 ROI를 쓰는 경우 ROI 나이·새 얼굴/가림을 검사한다. 품질 기준 미달이면 해당 특징만 보류한다.

30fps 경로의 프레임별 처리 예산은 우선 약 33ms로 두고 p50·p95·최대값, 입력·처리·추론·누락 수를 함께 계측한다. 파형 필터·피로 모델은 프레임마다 다시 실행하지 않고 수치 창이 준비될 때 수행한다. 예산을 못 맞추면 실제 표본율에 따라 지원 특징을 제한하거나 추출기를 개선한다.

### 모드 C

동시 경로는 일반 기능과 분리한 연구 옵션으로 검증한다. 흐름은 `명시적 동시 측정 선택 → 카메라 동의 → 화면 공유 동의 → 보이는 Activity에서 camera·mediaProjection 서비스 시작 → 다른 앱 전환`이다. 동의 취소·Activity 미복귀 상태에서는 서비스 시작을 보류하고 정리한다.

필요한 카메라 런타임 권한과 camera 전경 서비스 유형을 추가한다. 서비스에 연결된 카메라 수명을 사용하고, Activity가 배경으로 갔다는 이유만으로 CameraX 바인딩이 끊기는 문제를 확인한다. `BOOT_COMPLETED`나 알림 배경 이벤트에서 카메라를 자동 생성하지 않는다.

검사 조건은 앱 전환, 선택 앱 공유/전체 공유, 카메라 사용 앱과 경쟁, 잠금, 권한 철회, 회전, 절전, 프로세스 중단, 사용자 중지다. 카메라 오류는 기존 화면 세션에서 부분 관측 사유로 처리한다. 기존 잠금·심한 발열 종료 규칙은 전체 자원 정리에도 적용한다.

정상 시작·정리·알림·카메라 사용 표시·수동 중지와 정책 적합성을 확인한 기기에서만 모드 C를 제공한다. A는 C의 성공 여부와 독립적으로 개발한다.

## 4 G2 재사용과 수치 검증

뉴로렌즈 JavaScript를 Android WebView로 통째로 실행하는 방식을 기본 구조로 삼지 않는다. 기존 Kotlin 화면 엔진과 새 순수 Kotlin 수치 모듈을 연결하고, 고정한 JavaScript를 비교 참조로 사용한다.

| 단위 | 재사용 | 필요한 개선·검증 |
|---|---|---|
| 눈 좌표 | `eyeUV`, `faceFeatures` | 좌우·회전·개방도와 품질 독립, 하방 시선 |
| 보정 | `fitGaze`, 검증 수학 | 보정/평가점 분리, 모바일 화면 긴 변 정규화, 표시 필터 배제 |
| 깜빡임 | 기존 이벤트 개념 | 누락·긴 감김·불완전·미완결 이벤트, 유효 시간 분모 |
| 피부 RGB | `sampleSkin`, ROI 품질 개념 | Android 색 변환, 피부톤·조도 탈락률, ROI별 관측 |
| rPPG | POS·CHROM·필터·후보 합의 | 미래 창·세션 추세 추정의 분리, 원시 신호·잡음·시간 정렬 |
| 모델 관리 | 해시·입력 계약·그림자·승격 구조 | EyeCare의 새 목표·신호 조합·기기 조건으로 승인 |

수치 검증에는 알려진 랜드마크·RGB 파형·누락·평탄·광학 색 변화·실제 연구 기록을 사용한다. 같은 정규화 수치 입력에 대해 JS↔Kotlin 차이를 확인하고, 다른 카메라 색 처리로 생긴 차이는 별도로 평가한다. 합성 파형 정답만으로 실제 사람 정확도를 승인하지 않는다.

온라인 모델에 미래 창·사후 보정이 섞이지 않게 오프라인과 실시간 경로를 고정한다. 출력은 특징 종류·원시/보정/추정 여부·품질·버전을 함께 가진다.

새 화면은 `화면 자극 분석`, `눈·맥박 측정`, `피로 추정`의 근거 범위를 사용자가 이해할 수 있게 표시한다. 휴대폰 사용 중 상시 응시 시간을 확보하지 않은 검사는 해당 구간의 실제 응시 시간으로 표시하지 않는다.

불완전 데이터에서도 기존 보고서 수집이 계속되도록 버전 계약을 먼저 정한다. 테스트용 센서·피로 기록은 실제 사용자 inbox와 분리한다. 피로 질문의 생략·지연 응답과 모델 보류를 점수 0으로 처리하지 않는다.

## 6 G4와 G5 모델 개발

30명 반복성 파일럿에서 안정적인 특징·조건과 응답 분포를 확정한다. 순간 질문의 이해·반복성이 낮으면 모델의 가중치보다 목표 질문과 검사 절차를 먼저 수정한다. 특징이 눈 피로보다 졸림·폰 자세를 주로 나타내면 혼동 요인 조정과 입력 범위를 바꾼다.

초기 모델은 사전 선택한 약 8~12개 특징부터 시작한다. 후보의 수와 규제 강도는 데이터 크기에 맞게 조정하고, 선택은 훈련/검증 내부에서 수행한다. 독립 사람 평가용 분할과 개인화의 미래 방문 평가는 별도다.

모델 학습 입력에는 현재 정답 응답을 넣지 않는다. PRE 응답·과거 기록을 사용하는 모델은 기준 모델에도 같은 정보를 제공한다. 모델마다 특징·품질 정책·척도·데이터 snapshot·분할·해시를 고정한다.

첫 모델을 앱에서 그림자 실행해 결과를 기록하고 실제 피로 수치 표시는 꺼 둔다. 잠금 시험과 실제 기기 전향 평가를 통과하면 해당 입력 조합과 조건에 한해 활성화한다. 이전 모델로 되돌리는 설정과 저장된 검사 재현을 확인한다.

| 화면 빛이 맥박으로 검출 | 표준 중립 구간 우선, 광학 잡음 판정·기준 센서 비교 |

| 피로 응답 범위가 너무 좁음 | 다양한 자연 사용 자료 확보, 임의 양성 라벨 생성 금지 |
| M4가 기준보다 나쁘거나 기여 불명 | 관측 엔진과 연구를 유지하고 모델·특징·프로토콜 재검토 |
| 모델이 높은 보류율로 좋은 성능을 보임 | 전체 대상·동일 출력 범위 비교, 지원 조건 축소 |
| 새 기기·안경·피부톤 조건에서 실패 | 해당 조건의 모델 결과 보류, 지원 범위를 명시 |

기기 검증에는 현재 Samsung SM-S936N과 다른 제조사/카메라 2종 이상을 포함한다. 100초 검사, 기존 30분 화면 분석, 가능한 동시 분석의 전력·열·실제 FPS를 같은 화면 조건 대조와 비교한다. 처리 시간의 합을 배터리 소비로 환산하지 않는다.

짧은 100초 검사의 배터리 % 변화는 해상도가 낮을 수 있으므로 반복 검사와 같은 길이의 화면 대조를 사용한다. 가능한 기기의 charge counter 또는 외부 전력 계측을 활용하고 방법·반복 수·분산을 보고한다. 모드 A/B의 100초 검사에서 열로 인한 중단이나 연속 검사에 따른 메모리 증가가 있으면 통합 완료로 승인하지 않는다.

## 8 다음 구현의 작업 순서

1. G0의 입력·시간·품질·검사·응답 계약과 기준 장비를 확정한다.
2. 모드 A의 카메라 기록·시계·원래 RGB·랜드마크·카운터를 먼저 검증한다.
3. 눈 이벤트를 수동 라벨과 비교하고, 동시에 POS/CHROM을 기준 데이터로 재생한다.
4. 시선 보정·독립 목표 검증을 추가한다.
5. 표준 검사와 기존 화면 세션 연결·내보내기를 통합한다.
6. 반복성 파일럿으로 특징·라벨·검사 길이를 확정한다.
7. M0~M4 비교·잠금 시험·그림자 실행 후 피로 점수를 적용한다.

각 단계 결과에는 잘 나온 예시와 실패 사례, 지원 조건, 다음 단계로 넘어갈 근거를 함께 남긴다.
