# EyeCare 0.9.0-alpha 검증 기록

## 이번 버전

- 세션마다 실제 카메라/화면 처리 FPS와 지연, 눈/거리 관측 비율, 최대 thermal 상태와 일시 중지 시간을 **로컬 진단**으로 기록한다. 이전 세션 JSON에는 이 항목이 없으므로 읽을 때 빈 진단으로 취급한다. 카메라 프레임, 화면 원본, 화면 텍스트, 앱 이름은 기록하거나 연구 서버에 보내지 않는다.
- 눈 관측이 어둡거나 가려지는 등 근거가 부족하면 원인과 조치를 UI에 보여준다. 상태별 진입/해제 지연과 비율 임계값의 여유를 두어 경고 깜박임을 줄였다. 추정 점수를 채워 신뢰도를 높이는 기능은 없다.
- 개인 보정 화면에 같은 산식 버전의 비교 가능한 보고서, 적격 체감 응답, 과거 자료만 사용한 순차 평가 쌍, 기간, 원점수/개인 참고값의 NRS×10 대비 평균 절대 차이를 표시한다. 차이가 커지면 개선 없음으로 표시한다. 표시 스위치는 로컬 설정이며 원점수·연구 기록을 바꾸지 않는다. 웹 대시보드에도 별도 표시 스위치와 같은 검증 수치를 제공한다.
- 휴식 알림의 실제 표시/선택/닫기/미루기/권한 손실과 휴식 타이머의 시작/완료/실제 휴식 여부를 로컬 이벤트로 구분한다. 타이머 만료만으로 실제 휴식이라고 기록하지 않는다. NRS 대응 수와 빠진 수를 보여주고 알림 간격 변경은 **제안만** 한다. 전후 변화는 인과적 효과나 치료 성능을 뜻하지 않는다.
- 사용자가 버튼을 누를 때만 HTTPS 릴리스 정보를 확인하고, 새 버전이면 Google Drive 페이지를 연다. 앱은 APK를 자동 다운로드·설치하지 않는다. 릴리스 정보에 버전과 APK SHA-256을 제시한다. 기존 패키지/서명으로 제자리 업데이트를 의도하며, 기존 로컬 DB/암호화 세션을 지우는 마이그레이션은 추가하지 않았다.

## 테스트 범위와 한계

- JVM 단위 테스트: 진단 누적, 안내 상태 전환, 보정 순차 평가, 휴식 이벤트 집계, 릴리스 정보 검증 등 **86개 통과**. `lintDebug`는 오류 0건, 경고 26건(주로 오래된 의존성/권장 API, 전화 전용 ABI)이었다. `assembleDebugAndroidTest`, `assembleRelease`도 성공했다.
- Android 계측 테스트: 오래된 로컬 DB의 세션/보고서/이벤트가 새 DB 버전에서 남는지 검사하는 테스트 APK를 빌드한다. 연결된 실기기가 없어 실행은 별도다. 기존 설치본의 암호화 익명 세션까지 포함한 제자리 업데이트도 실제 기기에서 검증해야 한다.
- 리서치 API 점검은 합성 기록만 이용했다. 익명 인증, 본인 소유 읽기, 중복 409와 본인 확인, 공개 anon/타인 읽기 거부, 갱신 후 소유자 유지, 거리 필드, NRS append/재시도/짝지은 브라우저 읽기 검사를 통과했다. 생성된 합성 관측은 삭제하지 않고 `synthetic-test-*`로 구분한다. 앱에서 실제 사람의 건강 기록으로 API 테스트하지 않는다.
- 실제 Galaxy S25+ 열, 전력, FPS, 카메라/거리 정확도와 휴식 알림 도달률은 실기기 반복 측정 전에는 주장하지 않는다. 비교 방법은 [0.8.0 검증 문서](VALIDATION_0.8.0.md)의 A/B 프로토콜을 따른다.

## 수동 업데이트 확인

설정의 업데이트 확인을 누르면 현재 버전과 공개 릴리스 정보의 버전 코드를 비교한다. 연결 오류 시 현재 앱을 그대로 사용한다. 새로운 APK는 게시 파일의 SHA-256을 확인하고, 동일한 앱 식별자와 서명일 때 기존 앱 위에 설치한다. 앱을 삭제하고 재설치하면 Android Keystore의 익명 계정 복구는 보장되지 않는다. 휴식·진단·세션 기록의 보존 역시 삭제가 아닌 제자리 업데이트를 전제로 한다.
