# EyeCare v0.3 개발 기록

기준: `EyeCare_PASSIVE_PRD_v0.3_2026-10-10.md` · 시작 버전: 0.2.1-alpha

## 0.3.0 첫 구현

- 30분 강제 종료 및 25분 단발 알림을 서비스 흐름에서 제거했습니다.
- 화면 켜짐 기준 누적 시간/경과 시간 기준의 `ReportScheduler`를 추가했습니다. 주기는 10~120분, 10분 단위이며 5분 화면 꺼짐은 휴식으로 인식합니다. 설정 변경은 서비스가 다음 1초 틱에 읽습니다.
- 화면 공유가 중지되어도 서비스, 주기 타이머, 사용 시간 기반 리포트는 유지됩니다. 공유 재개에는 새로운 Android 화면 공유 동의가 필요합니다.
- 1분마다 현재 EFS를 계산하고 주기마다 별도 리포트로 저장합니다. `efs-heuristic-0.3`의 U01·S06·S08 앵커만 사용하며, 사용 불가 지표는 0점으로 대체하지 않습니다. 입력 ID, 화면 관측률, 낮은 신뢰도를 함께 저장합니다.
- 리포트 알림, 상세/NRS 0~10 응답, SQLite DB 버전 3의 `care_reports`·`care_events`, JSON 내보내기 형식 3 및 수집기 수용을 연결했습니다. 연구 기록 자동 삭제를 멈췄습니다.

## 0.3.1 후속 구현: 카메라 관측 기반

- 케어 시작 시 카메라 권한을 요청하고, 허용된 기기에서 전면 Camera2 영상을 화면 공유와 함께 관측합니다. 640×480 근처 YUV 출력을 고르고 MediaPipe Face Landmarker를 VIDEO 모드에서 실행합니다. 목표 30fps에 대한 실제 처리 FPS는 리포트에 기록하며 기기 성능은 아직 측정하지 못했습니다.
- 얼굴·눈 랜드마크와 눈 블렌드셰이프 일부, 얼굴 변환 행렬을 수집합니다. 눈 개방도와 좌우 차이, 홍채의 눈 안 상대 위치 및 10초 상대 움직임 안정성을 계산합니다. 닫힌 눈, 얼굴 미검출, 눈 형태 실패를 구분합니다. 절대 시선 좌표나 화면 응시 여부는 추정하지 않습니다.
- SQLite DB 버전 4에 `eye_dense`를 추가하고 프레임별 원자료를 저장합니다. 완료 세션에서 별도 `CSV.gz`로 내보낼 수 있습니다. 정기 리포트에는 처리 프레임 중 눈 검출 비율, 처리 FPS, 평균 눈 개방도, 최근 상대 움직임 상태를 보존합니다. EFS 계산에는 아직 눈 값을 넣지 않습니다.
- 화면이 꺼지면 카메라를 해제하고 다시 켜지면 재시도합니다. 화면 공유가 중지되어도 서비스의 카메라 관측은 유지하도록 연결했습니다. 카메라 오류 후 재시도는 5초 간격입니다. 단말 제조사별 재획득과 장시간 부하는 실기기에서 확인해야 합니다.
- 카메라 프레임이 SQLite 저장 속도보다 빠를 때 서비스 작업 대기열이 무한히 쌓이지 않도록 전달 중인 프레임을 1개로 제한합니다. 따라서 저장 FPS는 카메라 입력 FPS보다 낮을 수 있습니다.

## 아직 필요한 PRD 작업

- RGB 화면 지표 S01~S17, 1Hz 원자료와 1분 창, 개인/세션 기준선. 현재 화면 엔진은 0.2.1 휘도 변화 분석입니다.
- `SensorHub`, 사용 문맥, 오디오/미디어 상태, 눈 깜빡임·감김·하품 이벤트 엔진, 거리·자세·조명·rPPG, 전체 블렌드셰이프 기록, 세션/개인 기준선. 현재 눈 관측은 F01·F06·F15·F16의 일부와 원자료 수집 단계입니다.
- 발열 단계별 축소와 카메라 실제 30fps·저장 용량·배터리 검증, 기기별 카메라 경쟁·재획득 실험. 카메라 고밀도 데이터 용량 목표 20MB/시간은 아직 확인하지 않았습니다.
- 3기준 비교, 도메인별 전체 EFS, 상세 지표와 종합 분석 문단, 알림에서 5분 쉬기/미루기/무음 설정, 선택 증상.
- 케어 데이와 여러 세그먼트 연결, 하루 이상 장기 세션의 내보내기 분할, 화면·센서 원자료 CSV.gz 내보내기 및 수집기 원자료 집계.
